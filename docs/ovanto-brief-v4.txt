## 0. 项目背景与目标
- 域名：ovanto.ai（已购入，全站统一【非 www】）
- 定位：AI 图片 / 视频在线生成工具站，免注册即用
- 首期 7 个页面，覆盖英语 / 意大利语 / 法语 / 荷兰语
- 目标：每页在各自语区 Google 排到目标词前十
- 画像参照：搜索与直访各占约四成（免注册工具的典型结构），首期把「直访可记、可拼」
  和「首屏可用」做扎实

## 1. 技术栈
- Next.js 14+ (App Router) + TypeScript + Tailwind CSS
- 渲染：**SSG 或 SSR**。禁止纯 CSR——爬虫首轮抓取必须能拿到 Title / Description / H1 与正文
- 部署：Vercel（或 Cloudflare Pages）
- 生成产物走 CDN，不落本地磁盘
- 缓存 / 限流：生产 Redis（禁止用内存计数）
- 生成服务与支付：见第 8、10 节

## 10. 支付与账号（**新增**）

10.1 核心原则：**免费全程零身份，只有付费才出现邮箱**
  - 免费档不得出现任何注册 / 登录 / 邮箱 / 信用卡要求（这是三个 H1 的承诺）
  - 付费走 **Stripe Checkout 的 Guest Checkout（游客结账）**：只填邮箱 + 卡号，
    **不建账号、不设密码**

10.2 完整流程
  1. 用户点付费档 → 跳 Stripe Checkout（携带所选型号与数量）
  2. 只填邮箱 + 卡号，付款
  3. Stripe webhook 命中 /api/stripe/webhook → 以该邮箱建账号 → 发放对应额度
  4. 发一封**带激活链接的邮件**到付款邮箱
  5. 用户后续登录：输邮箱 → 收激活码 → 会话建立（**全程无密码**）
  6. 已付款用户由 cookie 会话自动登录，额度即刻可见

10.3 实现要点
  - webhook 必须验签；重复回调要幂等（以 Stripe event id 去重）
  - 额度入账与「已支付」状态必须同一次事务提交，不允许只入账不改状态
  - 订单、额度、邮箱三者要能互相追溯（对账用）
  - 收款主体：香港个人账户（最省事的路径）；备用 Stripe / Paddle / Creem
  - 密钥占位：[[STRIPE_SECRET_KEY]] [[STRIPE_WEBHOOK_SECRET]]（写入 .env）

10.4 免费档转付费的落点
  付费门槛**只放在型号 / 清晰度 / 时长的选择上**，不放在页面文案上：
  用户在 480p→1080p、5s→10s、免费模型→付费模型之间切换时看到价格。
  额度用尽时提示「今日免费额度已用完」，并给出付费入口，不做拦截式弹窗。
